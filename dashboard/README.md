# React Security Dashboard

Owner: Member 6
Reviewer: Member 1

## Purpose

The dashboard provides a security-focused interface for the API-Sentinel system.

It will present runtime API security findings and operational status without exposing secrets, credentials, personal data, raw packet captures, or other sensitive evidence.

## Planned Views

### Endpoint Inventory

Display discovered API endpoints and their status, including:

- documented
- undocumented
- deprecated
- shadow API findings

### Alerts

Display security alerts generated by the API-Sentinel detection pipeline.

Alerts should support investigation without exposing sensitive request data.

### Triage

Provide security findings with enough information for investigation and remediation, including:

- affected endpoint
- finding type
- severity
- status
- relevant security context
- remediation state

### Evidence

Display masked and privacy-safe evidence associated with security findings.

Sensitive values such as:

- passwords
- bearer tokens
- cookies
- personal information
- private keys

must not be displayed or stored by the dashboard.

### OWASP Mapping

Security findings will be mapped to relevant OWASP API Security Top 10 categories where applicable.

### Performance and Health

Provide operational views for:

- request/event processing health
- latency measurements
- service/component health
- alert and detection status

## Security Requirements

The dashboard must:

1. Enforce authentication and authorization for protected views.
2. Prevent unauthorized users from accessing security evidence.
3. Avoid displaying secrets or sensitive personal information.
4. Use masked evidence for investigation views.
5. Handle malformed or unexpected API responses safely.
6. Avoid leaking sensitive information through UI errors or logs.
7. Include authorization tests for protected dashboard functionality.

## Testing

Dashboard changes should include relevant automated tests.

Tests should cover, where applicable:

- authorized access
- denied access
- malformed input
- API failure handling
- sensitive-data masking
- protected evidence access
- UI behaviour for security findings

## CI and Security Checks

The dashboard will participate in the project security pipeline.

Planned checks include:

- React linting
- React tests
- package/dependency audit
- secret scanning
- static analysis where applicable
- container scanning when the dashboard container is introduced
- SBOM generation as part of the release evidence

## Evidence

Changes should provide reproducible evidence where relevant, such as:

- test results
- security scan results
- screenshots
- measurements
- reproduction steps

Evidence must not contain real credentials, personal data, production information, raw packet captures, or sensitive logs.

## Known Limitations

The dashboard is currently in the foundation phase.

The backend API contracts, detection data, enforcement data, and authentication integration are being developed by other project components. Dashboard interfaces will therefore initially use controlled test fixtures until the required APIs are available.

## Ownership

Member 6 owns the dashboard implementation and dashboard-related tests.

Member 1 reviews security-sensitive dashboard changes.

Changes must follow the repository contribution and security policies.
